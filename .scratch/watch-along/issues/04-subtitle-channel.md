# 04: 字幕通道

**What to build:** 屏幕上出现一行字，两秒左右之后它变成一条 `ocr` 事件进队列；只出现一次，且不会因为一次识别抖动就把错字写进去。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 常驻 OCR 服务加载完成时间 < 3 秒，且只加载一次（不是每次调用都加载）
- [ ] 同一行字第一次扫描不收录，第二次（间隔 ≥1.2 秒、相似度 ≥0.85）收录
- [ ] 收录时文本取**第一次**识别结果
- [ ] 乱码、过短（无语义）的结果不进队列
- [ ] 三带并发一轮总耗时 < 800 ms
- [ ] 屏幕文字变化后 2 秒内出现对应的 `ocr` 事件，`text` 不超过 60 字

- [x] 同一句不重复发（去重生效：42 秒窗口里 3 条，不是 38 条）

## 再验（2026-11-21 09:13）：识别范围包含整个屏幕区域

`text` 里出现 `口(W) 帮助(H) 关于(A)`（mpv 菜单栏）、`发现应用 设置M 已完`、`录t 5天前 2. 刚 5小时前`
（WorkBuddy 侧栏）——说明 region 那块矩形里显示的**不止视频**，被别的窗口盖住了一部分。

结论不变：**抓的是屏幕像素，遮挡/叠加都会进画面**。要干净的字幕，要么让目标窗口独占那块区域，
要么改回分带（只裁字幕所在的一条，不读菜单栏和侧栏）。

## OCR 准确率：定性结论（2026-11-21 12:28）

用 B 站硬字幕当基准，截 5 个时间点逐条比对。**方法有瑕疵**（截的是整页而非全屏播放器，
后两次收窄/裁剪失败），但**已足够判断准确度**——因为读到的句子能和字幕逐字对上：

| 时刻 | 字幕（基准） | OCR 读到 | 差 |
|---|---|---|---|
| 60s | 就咱们一个宿舍顶着**17**级台风打牌 | 就咱们一个宿舍顶着**＋七**级台风打牌 | 1 字 |
| 180s | 谁搞的恶作剧 | 谁搞的恶作剧 | 0 |
| 300s | 电话现在打不通 | 电话现在打不通 | 0 |
| — | 不知道发生了啥情况 | 不知道发生了啥情况 | 0 |
| — | 二楼以上的赶紧撤 | 二楼以上的赶紧撤 | 0 |
| — | 别碰 | 别碰 | 0 |

**结论**：字幕这种"白字带描边"的文本，OCR 基本能整句读对，偶有数字/符号被读成近形字
（`17`→`＋七`）。

**真正的短板不是准确率，是取材范围**：同一区域里还有
`Ai看剧的小伙柴`、`bilibili`、`4:05:00`、`《反相之地》最 未删减`、`4人正在看`、弹幕输入框。
这些都会被拼进 `text`，把一句好好的台词挤到 60 字之外。

**下一步（按性价比）**
1. 按实测位置裁字幕带（0.72–0.92），比整幅少 80% 的无关字
2. 加"常见 UI 词表"过滤（bilibili / 正在看 / 删减 / 弹幕 / 播放量）
3. 这两条都比换模型便宜得多，先做这个

**方法教训**：截图必须对准"播放器区域"，且要在**播放中 + 鼠标移开**时截；
暂停时控制条和弹幕框会浮上来，正好盖住字幕区。
