## 切句改造的实测（2026-11-21 09:18）：**退步了，需要回退或重做**

- [x] `0x800401f0` 已修（多线程服务要每线程 `CoInitialize`）
- [x] 采样率正确（要 16k 给 32000 帧 = 2.00s，不是错位）
- [ ] **转写质量比改造前更差**：
      改造前（单窗口 8 秒）：`真的非常感谢你们给我的支持` —— 完整、正确
      改造后（累积 + 只发句尾留余量）：`不分有` —— 碎片、无意义
- [ ] 累积逻辑的疑点：`tail` 从 `emitted` 开始截，**起点落在句子中间**，
      送进 Whisper 的是一段"从句中开始"的音频，模型缺少上下文，容易吐出无意义短句

### 判断
累积式切句的思路没错（按句切而不是按时刻切），但**实现方式错了**：
应该"整段转写、只交付已完成的句子"，而不是"从上次的句尾开始转"。
后者把上下文丢了 —— 而 Whisper 在短片段上极度依赖前文。

### 下次改法
1. 每次转写**整个缓冲**（最近 30 秒），不要从 emitted 截尾巴；
2. 用一个 `delivered` 集合按 `(t0,t1)` 去重，把已经发过的句子过滤掉；
3. 仍然只交付"尾部留 0.8s 余量"的句子。

这样既保住了上下文，又不会重复发。

- [x] 句子完整、语义连贯，内容与画面（切点检测/hue 饱和度）对得上
- [x] 延迟：`ms` 150–540，随缓冲增长略升，仍在预算内（20 秒缓冲约 270ms）
- [ ] **去重仍不够**：同一句会以不同 `(t0,t1)` 重复出现
      原因：Whisper 每次对同一段音频的切分边界会变，`(t0,t1)±0.35s` 挡不住
      （例如 `低饱和像素的色相没有意义` 出现过 t0=0 / 4.9 / 0 三种起点）
- [ ] 缓冲裁剪后时间码平移了，但 Whisper 对新缓冲重新切分，位置又变 —— 去重更难

### 下次的改法
**按文本去重，不按时间码**：Python 侧归一化（去标点/空白）后存 set，
命中就不交付；保留 `(t0,t1)` 只作展示。JS 侧已有类似规则（相似度 0.9），
但要降到 0.8 才能挡住 `2是…` / `二是…` 这种一字之差。

## 去重第二轮实测（2026-11-21 09:25）：仍然漏，原因换了

- [x] 整句质量好：`新的口径问变了多大面积`、`这把幅度门槛换成了面积门槛`、`任何阈值都分不开`
- [x] 一字之差（是/式、夜戏/夜系）已能被模糊判重挡住
- [ ] **同一段音频这次是长句、下次是短语**：例如
      `也就是说,原来的口径问变了多少,新的口径问变了多大面积。`
      下一次变成 `也就是说` / `原来的口径问变了多少` / `新的口径问变了多大面积` 三条
- [x] 已补"包含即重复"（≥4 字且一方含于另一方）

### 但这是治标
根因是**同一段音频被反复转写**：缓冲每加 3 秒就整段重转，Whisper 每次的切分点都不同，
于是同一段内容每次都换个形状出现。文本去重只能事后补救。

### 下次的正解（设计层面）
**每段音频只转一次**：
- 只送"新音频 + 1.5 秒前摇"（前摇只为给上下文）
- 交付时丢掉落在前摇区间里的句子
- 这样每次处理的是**互不重叠**的音频，切分稳定，去重也就不需要了

代价：缓冲区边界仍需裁剪，但不再整段重转，`ms` 也会更低（现在 250–340ms 主要是重转 20 秒）。
