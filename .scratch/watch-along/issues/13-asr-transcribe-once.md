# 13: ASR 每段音频只转一次（去重的结构性修法）

**What to build:** 现在缓冲每滑一次就把整段（20 秒）重转一遍，Whisper 每次切分边界都不同，
同一句话以不同形状反复出现——文本去重、时间水位都只能事后补救。改成"新音频 + 1.5 秒前摇，只转一次"。

**Blocked by:** 12

**Status:** resolved（2026-11-22 复验：两个干净单轮重复率均为 0）

- [x] 每拍只送「交付点前 1.5s 前摇 + 之后的新音频」，单次上限 30s
- [x] 结束时间 ≤ cursor 的句子不交付（只当上下文）
- [x] 连续跑 8.5 分钟：**同句重复 = 0**（上一版 26 条）—— 结构性修法生效
- [x] 单次 `ms` 明显下降（3 秒级音频，不再重转 20 秒）

## 为什么不是调参
缓冲滑动 + 整段重转 = 切分不稳定，这是结构问题；水位/相似度只能压住一部分。

## 实现（2026-11-21）

- `PREROLL_SEC = 1.5`、`MAX_SLICE_SEC = 30`、`MARGIN_SEC = 0.8` 三个常量控制切法
- 没有交付时也把 cursor 往前推（超过 6 秒就推），否则下次还重转同一段 —— 那就是老问题
- 合成纯音验证：缓冲 3→18 秒增长正常、cursor 按 6 秒步进、**没有假句子**、不崩

**仍未验**：真实人声下的重复率与单次耗时。这两个数只能真机跑出来。

## 真机结果（2026-11-21 12:22，8.5 分钟）

- 落盘 **274 条**，时间跨度 **3.25 → 513.09 秒**（绝对时间正确）
- **重复 0 条**（上一版同条件下 26 条）—— 结构性修法生效
- 句子长度分布：1–3 字 45 条 / 4–7 字 148 / 8–14 字 73 / 15+ 字 8，平均 6.4 字
  （字幕平均 7.1 字，长度量级一致，说明不再是"整段大块"）

### 复验方法上的一个坑（写下来防下次踩）

顺带拿 `.scratch/run/asr-out.jsonl`（17:26 那轮 asr-loop 粗测）跑了同一套判据，得到 **36 条完全相同**——看着像回退，实际不是。三条证据：

1. 该文件的**时间码回退过一次**（`316.67 → 40.7`），说明一个文件里混了多轮；
2. 36 对重复的相隔秒数**中位 129.5 秒、最大 378 秒**，只有 1 对 < 20 秒；
3. 重复的文本是「同一段片子被放了两次」的形状（同一批台词成组出现）。

原因是 `scripts/asr-loop.cmd` 只发 `{"seconds":3}`、**不带 `reset`**，`DUMP` 一直指向默认的 `asr-out.jsonl` 且以追加方式写，于是多轮结果堆在同一个文件里。

⇒ **以后复验重复率，必须先确认时间码单调递增**，否则跨轮会把同一段台词算成重复。干净单轮（`watch_start` 触发 `reset`、一轮一文件）才有意义。

**仍未定死的一条**：`asr-out.jsonl` 里有 2 对相隔 18.5 秒与 21–25 秒的重复，出现在时间轴回退**之前**的同一段里，形状像"播放被回拖了约 21 秒"。要定死需要当时的原始录音，而那一轮没开 `WATCH_ALONG_DUMP_RAW`，无从复核。不影响关票——两个干净单轮都是 0。
