# 实时陪看（watch along）

## Problem Statement

在电脑浏览器里看直播或长视频时，用户希望 AI 能同步看着同一个画面、听懂在说什么，并像坐在旁边的人一样随时接一句。现在的 AI 只能看到用户手动截图的那一瞬间：它不知道刚才三分钟发生了什么、谁说了什么、屏幕上写了什么；想让它"陪着看"，用户得不停地截图、复制、解释。

## Solution

一个 DSH 插件。用户说一句"陪我看这个"，插件就开始盯住那个直播间窗口，把三件事持续变成一条**文字事件流**：

- **画面**：只记录"变了多少、变在哪里"，并在值得看的时候把若干帧合成**一张拼图**；
- **字幕**：读屏幕上的文字（字幕、弹幕、标题），只在文字稳定后收录；
- **声音**：从系统输出环回录音，切句后转写成带时间码的台词。

AI 用长轮询读这条流，需要看清细节时再单独要一张图。同一个接口也供手机通过局域网读取——手机只拿文字和图片链接，不搬像素。

## User Stories

1. As a 看直播的用户, I want 在对话里说一句"陪我看这个窗口"就开始盯着看, so that 我不用打开任何设置面板。
2. As a 看直播的用户, I want 它按窗口标题找到那个直播间, so that 我不必手动输入坐标。
3. As a 看直播的用户, I want 拖动窗口后它仍然看正确的位置, so that 画面不会错位。
4. As a 用户, I want 窗口被关掉或最小化时收到一条明确的错误, so that 我知道不是 AI 不理我。
5. As a 用户, I want 画面变化变成简短的事件（强度、位置、幅度）, so that AI 不必为每一帧付费。
6. As a 用户, I want 画面足够有意思时拿到一张**拼图**（多帧按重要性排进格子）, so that AI 一次能看懂一段时间的节奏，而不是只看一帧。
7. As a 用户, I want 静止的画面**什么事件都不产生**, so that 它不会一直打扰我、也不会白烧钱。
8. As a 用户, I want 快速连续的变化被识别成"一直在动"而不是"不停切镜头", so that 它的评论不会碎成一条条。
9. As a 用户, I want 说"现在什么样"时立刻拿到一张最新的图, so that 我不用等下一批。
10. As a 看直播的用户, I want 它读出屏幕上的字幕和弹幕, so that 即使声音听不清，我也知道大家在说什么。
     - **仅字幕，弹幕不做**（2026-11-21 用户决定）。原因：弹幕一直在动，
       "两遍一致才收录"这条防抖规则会把它自然挡掉；要读弹幕就得为 middle 带另立规则
       （更松的阈值 + 限流），会让事件密度从 5.4 升到 8–10 条/分钟。
       现状：middle 带会读到一部分（画面稳定时），但不保证。
11. As a 用户, I want 同一行字被识别两次一致才收录, so that OCR 的错字不会变成"AI 说的内容"。
12. As a 用户, I want 它听懂主播和队友在说什么, so that 它能接上具体的对话。
13. As a 用户, I want 它不要把"谢谢观看""字幕由某某提供"这类套话当台词, so that 它说的话可信。
14. As a 用户, I want 画面、字幕、声音的事件共用一条时间轴, so that 它能对上"第 12 秒画面变了，同时有人说了一句话"。
15. As a 用户, I want 断线或跳过一段时间后仍能拿到漏掉的事件, so that 不会出现"它说没发生什么"而其实发生了很多。
16. As a 用户, I want 它主动说话的频率有上限（默认每分钟 6 条）, so that 陪看像聊天而不是弹幕播报。
     - 细化（2026-11-21 敲定，见票 11）：默认**关**；只在 `strength=high` / `cut=true` 时唤醒；
       最小间隔 120 秒可调；唤醒发到"最后一次 watch_start 的会话"；连续 5 次无回应则本次陪看停；
       拿不到宿主能力时静默降级。术语：wake（塞 user 消息）/ 台词 / 播报（TTS）/ 插话（要避免）。
17. As a 用户, I want 在手机上也能收到同样的文字和图片, so that 我躺着也能看。
     - 边界（2026-11-21 用户决定）：**只做接口，不做页面**。手机端拿 JSON/PNG 自行展示；
       之前实现过一版单文件 HTML 页面，已按此决定回退删除。
18. As a 用户, I want 图片链接有时效、过期即失效, so that 链接被转发出去也不会一直可用。
19. As a 用户, I want 同一个事件只对应一张图、重复请求走缓存, so that 不会反复生成同一帧。
20. As a 用户, I want 某个通道坏掉时其余通道继续工作（显卡出问题只影响台词）, so that 不会因为一个零件全停。
21. As a 用户, I want 参数改坏时看到明确原因, so that 不会"永远不停"或"立刻停"。
22. ~~As a 用户, I want 用场景预设（游戏 / 讲课 / 影视）一次调好一组参数~~（**已取消**，用户 2026-11-21 决定，见票 07 结票；`settings.mjs` 里没有 `PRESETS`，也没有任何 preset 入口）

24. As a 用户, I want 手机断开后不必重新开启监听、网络抖一下自己恢复, so that 我不用每次重新下命令。

## Implementation Decisions

### 形态与进程

- 一个 DSH 插件；采集循环跑在插件进程内，Python 只作常驻子进程（OCR、录音、转写）。电脑端优先，手机端预留接口。

### 画面

- 采集用 ffmpeg `gdigrab` 抓窗口区域，**必须显式指定 `engine:'gdigrab'`**——参考库 0.2.5 的 `isDda()` 没判断 region，会误加 `hwdownload`，导致一帧都出不来。
- 变化判据、档位分配、拼图排布、token 预算全部**原样复用参考库 dsh-see-now 0.2.5**，算法不改，只写接线（见 ADR 0001）。
- 窗口在启动时按标题片段找一次；每 2 秒比对矩形，变了就重启采集（约 0.4 秒断流）。
- **任何采集结束都按故障处理**：三条通道一起停、报错、写日志。不区分"用户关窗口"与"采集中断"。
- 静止画面零事件；连续运动被运动补偿吸收，不产生切点。

### 字幕

- 三条重叠的横向带 + "两次识别一致"（间隔 ≥1.2s、相似度 ≥0.85，落盘用第一次的版本）——这条机制**保留不变**。
- OCR 引擎换成 RapidOCR + **PP-OCRv6_small**（ONNX Runtime），通过参考库自带的可插拔接口接入（见 ADR 0002）。
- 那个接口是"每次调用起一个命令"，而模型加载要 1–3 秒，所以 OCR 必须做成**常驻服务**，接口里只写一个约 20ms 的客户端。
- 放大倍数不照抄参考库的 2×/3×（那是给 Windows OCR 试出来的），用真实截图扫出最小值。

### 声音

- WASAPI 环回（默认输出设备）→ 16k 单声道 → VAD 切句（动态范围 <6dB 时不切）→ **faster-whisper large-v3-turbo**（GPU）→ 幻觉过滤。
- **不做人声分离、不保留 SenseVoice 快档**（见 ADR 0003）。GPU 不可用时显式报错，不许静默变成没有字幕。
- 句子封顶 3 秒；时间码一律用 epoch 毫秒，不用样本数累加。

### 事件与传输

- **一条**队列，画面/字幕/声音共用递增 id；事件只含数字、文字与图片引用，**不含像素**。
- 字幕事件携带识别出的那行字，超过 60 字截断。
- 读用长轮询：请求带 `sinceId`，返回最早未读 + `pending` / `truncated` / `nextId`；id 有高水位线，清空不归零。
- 容量：内存环形 500 条，磁盘 2000 条；`sinceId` 早于内存最旧时标 `staleSince` 并从最旧给起，**不静默跳过**。
- 手机端：HTTP 长轮询传事件；图片走带 token 的签名 URL，一个事件一张图，重复请求给 304。
- 手机端口由插件自己开，绑局域网，**默认关闭**，空闲 30 分钟自动关；token 与端口同生共死，URL 里的 `exp` = 最后一次请求 + 30 分钟。
- 来源限制：IPv4 私有段 + IPv6 `fe80::/10`、`fd00::/8`、`::1`。

### 设置

- **首项是「环境检查」**（2026-11-23 恢复 UI，票 07 当时是"不做 UI、只留逻辑"）：八条只读检查（Python 版本 / 三个包能否导入 / ffmpeg 版本 / NVIDIA 驱动 / CUDA 能否加载 / OCR 模型 / Whisper 模型文件 / 默认输出设备），绿黄红三态；失败时只显示一句原因，**不提供任何一键下载**——环境须用户自备。
- 照参考库的形态：前端是零构建的模块加载包，挂在宿主设置页；后端两条同源路由（读状态 / 写配置），**校验只在后端**，前端只显示后端给的 `warnings`；非法值返回 200 + `rejected`。
- 常用项：窗口标题、画质档、**传图档位（不传 / 低清 640 / 高清 798）**、字幕开关、声音开关、陪聊提示词、静默观察间隔、主动说话间隔。
- ~~场景预设三个：游戏（12fps / 高画质 / dense / 4 条每分钟）、讲课（8 / 中 / normal / 6）、影视（8 / 高 / calm / 3）。~~ **已取消**（用户 2026-11-21 决定）：参数逐个暴露，不再做一键预设。
- 高级折叠只放裸阈值；**改完重开 DSH 生效**（不做即时生效）。

### 对外接口

**工具（AI 侧）**

| 工具 | 作用 | 关键参数 |
|---|---|---|
| `watch_windows` | 列出可见窗口标题 | — |
| `watch_start` | 开始盯一个窗口 | `window`（标题片段） |
| `watch_events` | 长轮询读事件 | `sinceId`、`wait`（秒）、`limit` |
| `watch_frame` | 取一张拼图 | `sheetId`（省略取最新）、`live`（立刻抓一张） |
| `watch_stop` | 停止 | — |
| `watch_status` | 各通道状态与最近错误 | — |

**事件字段**（共有）：`id`、`t`（相对秒）、`at`（epoch ms）、`kind`。

- `motion` → `strength` / `where` / `peak` / `cells` / `sheetId?`
- `ocr` → `band` / `text`（≤60 字）/ `stableMs` / `hits`
- `speech` → `text` / `t0` / `t1`

**长轮询返回**：`ok`、`now`、`pending`、`truncated`、`nextId`、`staleSince?`、`timedOut`、`events[]`。

**通道状态**：`idle` / `running` / `degraded` / `failed`，失败时附 `reason`。

**配置文件**：设置页读写宿主配置目录下的 `watch-along.json`；`env.json` 由安装脚本生成、插件只读，用来定位 venv 与模型。

**手机路由**：`GET /events?sinceId=&wait=`（同长轮询返回）、`GET /frame/<sheetId>?token=&exp=`（PNG，重复请求 304）、`GET /status`。

## Testing Decisions

### Seam

**一个 seam：`WatchService` 门面**——起停、读事件、取图、查状态。工具与 HTTP 都只是它的薄适配器，测试只打门面。

理由：两条传输面（工具 / HTTP）各自测会测出两套行为；收敛到一个门面，传输层退化成参数转发，也就无法悄悄分叉。这是能覆盖全部外部行为的最高层。

门面之外可注入三个替身，把"慢且不确定"的东西换成确定的：

- **帧源**：合成帧序列代替 ffmpeg（可精确控制静止 / 切镜 / 连续运动）
- **OCR**：固定返回值代替常驻服务
- **转写**：固定返回值代替 GPU 推理

### 什么算好测试

- 只断言**外部可观察的行为**：事件字段与顺序、`sinceId` 的补齐语义、图片是否存在、错误是否被报出来。
- 不断言内部调用次数、不断言中间变量、不断言具体阈值常量（那些会变）。
- 时间相关的用**假时钟**推进，不 sleep。

### 要覆盖的行为

- 静止画面：零事件。
- 合成切镜序列：出事件，强度与位置合理。
- 连续运动：不出切点事件。
- `sinceId` 落后到超出内存：返回 `staleSince`，且不丢中间事件。
- 窗口矩形变化：采集被重启，新事件时间码连续。
- 字幕两次一致：第一次不收录，第二次收录，文本取第一次。
- 幻觉词：被过滤。
- GPU 不可用：返回明确错误，不返回空字幕。
- 手机：token 过期被拒；同一 id 重复请求 304；空闲超时后端口关闭。
- 故障注入：杀掉 OCR 服务，字幕停但画面继续。

### Prior art

- `vendor/dsh-see-now-main/test/`（`node --test`，覆盖判据、档位、拼图、token 估算）
- `vendor/dsh-better-ears-main/test/`（11 项离线测试：注册、报告、状态、设置 API token）
- 两者都是纯 Node 测试、无外部服务、用合成数据，直接照这个形状写。

## Out of Scope

- 人声分离（BGM 压过人声时的补救）——以后作为开关加
- SenseVoice 或其它快速档
- 悬浮窗与任何界面开关
- 分块检测、动态 ROI
- 输出设备变更跟随（换音箱后需重启插件）
- 设置即时生效
- 手机 App / 手机端插件（这一期只做电脑侧接口）
- AI 语音回复（TTS）
- 多显示器与负坐标

## 追加需求（2026-11-21 11:36，用户确认要做）

17. **图片走子代理**：取到的图不再默认进主会话，交给一次性子代理看，主会话只收结论。
    理由：图会长期占据上下文，看一小时就"变贵"。（票 16）

18. **OCR 回到分带**：整幅识别会把菜单栏/侧栏/正文混成一句，`text` 远超 60 字上限。
    带的位置必须**先实测再定**，不许拍脑袋。（票 14）

    理由：现在会录到自己念的话、录到微信提示音；进程回环还顺手解决了换设备的问题。（票 17）

20. **人声分离不做**（用户 2026-11-21 明确否掉）——虽然 soundtry 认为它是 BGM 铺满时的
    最大准确率杠杆，但代价（模型 + 算力 + 调试）不值得。

21. **防幻觉两道都要**：源头（没人声不送识别器，已有 `vad_filter`）+ 事后（词表/长度/字符多样性）。
    事后这半原先漏做，已于 2026-11-21 补上。


22. **设置界面不做**（2026-11-21 用户决定）：宿主 composition 不发放客户端服务，
    手写 client 六种写法全部排除。逻辑层（设置模型/校验/环境检查/持久化）保留，
    将来若要界面，走插件自己的 HTTP 页面，不再依赖宿主。


23. **采集改为 koffi 直抓**（2026-11-21 用户决定，见 ADR 0005 / 票 20）。
    原 ffmpeg(gdigrab) 路线在窗口化场景下坐标不可靠（DPI 换算错两次），

    三带比例与门限照抄 streamvision（0–0.38 / 0.32–0.72 / 0.66–1.0，1200ms，0.85），
    放大量按带宽度自适应（<1200px 才放大）。遮挡仍然无解，接受。

## 收口状态（2026-11-23 08:20，第一版）

20 张票全部关闭。以下是**代码实际长什么样**，与前面章节冲突时以本节点为准。

### 两条消息通道（形态不一样）

| 通道 | 频率 | 消息里有什么 | 为什么 |
|---|---|---|---|
| 静默观察 | 每 6 秒（最低 6，填更小按 6 存） | 图 + 最近 3 秒事件的 JSON + "一句话总结"提示词 | 让它一直知道剧情 |
| 主动说话 | 每 30 秒 | **只有提示词**，不带图、不带事件 | 观察轮已经把画面写进上下文，再塞一遍只是慢 1–2 秒 |

图以附件形式随消息走（不是工具调用）；宿主不认 `image` 块时会自动退回纯文本。

### 传图三档（设置可调）

`imageQuality`: `none`（不传）/ `low`（640 宽，默认）/ `high`（798 原尺寸）。
选 `none` 时连"强制看图"一起关——否则它会为了看图去调工具，而工具最后还是要传图。

### 开场只调两次工具

`watch_status`（可选）→ `watch_start`。`watch_start` 自己就返回**首帧 + 最近 10 秒字幕**，
不再需要追一次 `watch_frame`（以前开场四连调，十几秒才出第一句）。
