## 一句话结论

两个项目不是竞品，是同一件事的**两端**：

- **see-now 强在「判得准、排得好」** —— 有完整的画面变化判据、密度分档、拼图算法，每条阈值都有实测和回滚记录。
- **streamvision 强在「采得省、传得轻」** —— 进程内采集、事件流、长轮询，像素根本不进上下文。

所以不是"各取一半拼起来"，而是**按两条路径分开用**：

| 路径 | 什么时候走 | 用谁的 |
|---|---|---|
| 连续路径（常开、便宜） | 一直在看，出文字事件 | streamvision 的采集 + 事件队列；判据换 see-now 的 |
| 回看路径（按需、贵） | "刚才那 20 秒给我看看" | see-now 的档位 + 拼图 + token 估算 |

## 1. 两个项目到底是什么

| | streamvision 0.2.7 | see-now 0.2.5 |
|---|---|---|
| 一句话 | 屏幕变化 → 文本事件流 | 屏幕变化 → 按重要性拼成一张图 |
| 采集 | **进程内** koffi 调 Win32 GDI（BitBlt + GetDIBits + JS 缩放） | **spawn ffmpeg** rawvideo 管道（ddagrab / gdigrab / 摄像头） |
| 判据 | 32×18 块平均绝对差，阈值固定下限 4 | **64×36 HSV** 加权差 + 亮度归一 + 黑边补偿 + 运动补偿 + 背景模型 |
| 留帧 | 过阈值就出事件（不攒） | 切点（地板+尖峰+不应期）/ 积分 / 兜底 三路 |
| 输出 | `events.jsonl`，一条事件 ≤300 字符，可带 PNG 路径 | 一张拼图（多帧按 1/k 档位排），带编号与时间码 |
| 读法 | 长轮询 `sv_events({wait})`，不唤醒会话 | 工具调用，请求才给图 |
| 成本模型 | 事件是文字，便宜；图另外取 | 按像素算 token，用档位和拼图摊薄 |
| 依赖 | 只有 koffi | 只 spawn ffmpeg（无图像库，自己写 PNG/点阵字） |
| 平台 | Windows only | Windows + macOS |
| 规模 | 104 KB / 17 文件 | ~500 KB 源码 / 191 文件（含 40 个测试） |
| 许可 | MIT | Apache-2.0 |

**两边都踩过、值得信的判断**：
- 阈值单位会跟 fps 绑死（see-now：批量版/实时版同名阈值**单位相反，抄表必错 30 倍**）
- 静止画面必须**零输出**（两边都在门控上花了大功夫）
- 溢出即丢失（see-now：44% 内容折进溢出文件没人读；streamvision：SVG 超 2400 字符就整段不给，只给路径）

## 2. see-now 值得直接拿的（文件级）

| 拿什么 | 文件 | 关键常量/做法 |
|---|---|---|
| HSV 打分 | `src/cuts.js` `scorePair` | 色相走环形最短边；色相按**两帧较低饱和度**降权（两个灰能差 85°） |
| 亮度归一 | 同上 `normalizeScore` | `REF_V=96` `GAIN_MAX=1.85` `NOISE_FLOOR=2`；暗场必漏的解法，不是调门槛 |
| 黑边补偿 | 同上 `barFraction/barRows` | 判"**整窗一直黑**"而不是"这一帧黑"，否则片头黑场会被当黑边 |
| 运动补偿 | 同上 `mcStats` | 邻域 `radius` 内找最像的，连最像的都超 `tau` 才算变；**先测同位置**把静止帧从 0.72ms 降到 0.06ms |
| 前景守卫 | 同上 `bgStats/bgKeep/bgBorderChanged` | "整屏前景停住"与"真切到新场景"像素级不可分，只能靠未来帧+外圈投票 |
| 切点判据 | `src/pipeline.js` `DEFAULTS` | 绝对地板 `cutAbs=12` + 尖峰比 `2.5` + 不应期 `0.4s`；**少一个都会被持续运动骗** |
| 积分采样 | 同上 | 阈值 = 参考强度 × fps × 秒数，**绝对值**；用"当前平均"会让等式两边抵消，退化成等间隔 |
| 密度档位 | `src/tiers.js` | 阈值单位是**帧/秒**（与 fps 脱钩）；只看过去；EMA 平滑；上下阈值各带 5% 滞回 |
| 拼图 | `src/pack.js` | DP 不做贪心；目标函数 `Σ面积 − 箱数×1.02`，**多一张图必须付钱**；行内拉平 + 纵向最多 1.3× |
| 画布 | `src/sheet.js` | 零图像库；5×7 点阵烧编号/时间码；格子间 1px 缝 |
| token 估算 | `src/tokens.js` | 14px patch 对齐、3:1 降采样 → `rows×(cols+1)+2`；**阶梯函数，不能按像素线性估** |
| 声音 | `src/listen.js` + `examples/floating-chat/listen.py` | 环回 → 16k 单声道 → 静音断句 → `seg-<epochMs>.wav`；**文件名带墙上时间**，因为 WASAPI 静音时不推数据，样本计时会漂 |

**它的坑也要继承**：`docs/cut-detection-limits.md` 写清了三件事靠调参解决不了（整屏前景停住、固定外框近景误挡、0.5 秒确认延迟）。我们要么接受误切，要么加语义。

## 4. 我们怎么取（决定 · 2026-11-21 02:5x 修正版）

> 修正说明：初版把 see-now 定位成"判据库"、把采集判给 streamvision。**这是错的**。
> 正确的切法是按**消费者**分：谁产出 AI 要看的**像素**，谁产出 AI 要读的**文字**。

### 取舍三条原则

1. **按消费者分，不按功能分。** 画面链路服务"看"，信息链路服务"读"。两条链路各自独立取舍，不交叉。
2. **画质由缩放算法决定，不由采集工具决定。** 见 §4.1 实测：同为 720p，面积平均比最近邻多读出 61% 的字。所以采集工具可以自由选（"程序任选"），画质标准必须锁死在 see-now 那一档。
3. **上限不花钱的地方要顶格，花钱的地方要门控。** 原生帧的代价在抓取（已付），不在缩放；token/带宽/转码才是要门控的。

### 4.1 决定取舍的那次实测（1920×1080 原生同一帧 → OCR 出字数）

| 处理 | 出字数 | 占原生 | 额外耗时 |
|---|---|---|---|
| 原生 1920×1080 | **1945** | 100% | 0（抓取已付 25ms） |
| box 缩 1280×720 | 1600 | 82% | +10.3 ms |
| nearest 缩 1280×720 | 995 | 51% | +3.0 ms |
| box 缩 853×480 | 263 | 13% | +6.5 ms |
| nearest 缩 853×480 | 195 | 10% | +1.3 ms |

**结论：糊的主犯是最近邻缩放，不是分辨率。** streamvision 的 `capture()` 用的是最近邻——它那 45–65ms 的"快"有一部分是拿画质换的。

### 4.2 所以采集这么定（最高上限，且几乎不额外花钱）

- **抓**：原生分辨率，进程内 koffi（不启 ffmpeg 子进程，不管进程死活）——1080p 区域 25ms
- **算分**：从同一张原生缓冲抽 64×36 给 `cuts.js`，几乎零成本
- **看**：原生**直出，不缩放**（缩放成本 0，因为它本来就不用缩）
- **发手机/省流**：box 缩 720p（+10ms，保住 82% 的字）；不够再要原生
- **落盘**：只在被请求时编码 PNG，不要每帧编码

### 4.3 模块归属（修正后）

| 环节 | 取谁 | 具体 |
|---|---|---|
| 画质标准 | **see-now** | `area`/box 面积平均（它实测拒绝 `fast_bilinear`：SSIM 0.877 vs 0.989） |
| 画面组织 | **see-now** | `tiers.js` 档位 + `pack.js` 拼图 + `tokens.js` 预算 + `sheet.js` 烧编号 |
| 采集实现 | **streamvision** | 进程内 koffi（但**缩放换成 box**，这是必须改的一行） |
| 信息：变化 | see-now 判据 + streamvision 事件格式 | HSV 三件套判定；事件里带 `strength/where/edgeDensity/bbox` |
| 信息：文字 | **streamvision** | 三带 OCR + 两次识别一致（≥1.2s / 0.85） |
| 信息：声音 | **see-now** | 环回 → 16k → 静音断句 → `seg-<epochMs>.wav` |
| 传输 | **streamvision** | 事件队列 + 长轮询 + id 高水位线 + 有界磁盘 |

### 4.4 明确不拿的
- see-now 的悬浮窗（`window.py` 108 KB + `glass_*.py` 一套）—— 用户明确不要
- see-now 的 ffmpeg 采集管道 —— 进程内更快，且画质标准可以用 box 自己实现
- streamvision 的**最近邻缩放** —— 这是它唯一实质性的画质缺陷
- streamvision 的块差分当**判定**用 —— 太粗，只留作"哪里动了"的描述
- streamvision 的 `sv_arm` 作为"进程内 watcher" —— 我们要独立进程，不受 agent 回合影响

### 4.5 我们自己的新东西
1. **三条通道分开**：事件（常开、便宜）/ 画面（按需、贵）/ 声音（补无字幕内容）。两个项目都只有其中一两条。
2. **双通道文字**：屏幕字幕 OCR（streamvision）+ 声音转写（see-now）。字幕通常比语音快且准；没字幕的内容靠语音兜。
3. **跨设备**：手机端插件订阅 + 按需拉图（它俩都是单机 agent 插件，没这个）。

### 4.6 最终定案（2026-11-21 02:55，用户拍板 · 覆盖以上细节）

**原则：只做兼容，少原创，少踩坑。**

1. **拼图方案原样用 see-now，不自创。** 作者踩过的坑（60×96 认不出、maxCrop 该为 0）直接白捡。
2. **不做「原生帧第三条腿」。** 账算不过来：拼图 798×450 = 222 token 装 6–9 帧；原生 1920×1080 顶到 1024 token 只装 1 帧，每帧成本差 25 倍。
3. **文字损失由 streamvision 的 OCR 补**（不是补像素细节）。它读的是原生屏幕像素，比拼图里被缩小的格子大 4–9 倍，所以更准。
4. **采集也用 see-now 的 `spawnFrames()`**，不自写 koffi。它是完整采集循环（背压、拼帧零拷贝、首帧计时），`onFrame({t,buf})` 正好对上 `pipeline.push({t,buf})`。
5. **已知限制**：see-now 的 ffmpeg 采集**不能跟随窗口**（region 在命令行里固化）。窗口钉住不动即可；移动了重启采集（首帧 ~400ms）。streamvision 能跟随是因为每帧重算矩形再 BitBlt——那是原创路线，不走。
6. **ASR 从关键路径挪出**：字幕/弹幕/PPT 由 OCR 覆盖，声音只补"没字幕的口播"，可最后做、做不成也不影响陪看。

1. **宿主 ASR 到底有没有**：see-now 说 DSH 桌面版自带 `speechToText`（SenseVoice）。我在这台机器的 `.dsh` 里没查到（profile 的 `node_modules` 是符号链接，grep 打不进去）。要验一次。

   **但这条在你这台机器上不成立**：我用 `soundcard` 录 3 秒、同时用 ffplay 播 440Hz，频谱主峰 **440.0Hz**（DC=0，主峰能量是次峰的 2 倍、是噪声中位的数倍）——录到的是真声音，不是噪音或串音。

## 7. 音频方案定案（2026-11-21 03:2x，质量优先版）

**四家的定位**：better-ears / soundtry / hear / qian-music。**四家都不抓系统声音**（全是喂文件的分析器），环回只能用 see-now 的 `listen.py` 或实测通的 `soundcard`。

**质量上限由 soundtry 决定，鲁棒性由 better-ears 决定。**

| 环节 | 取谁 | 依据 |
|---|---|---|
| 人声分离 | **soundtry** | MDX-Net ONNX，默认 `--separate=true`；BGM 铺满时是最大的准确率杠杆 |
| ASR 引擎 | **soundtry** | 默认 `--model medium --device cuda --beam 5`，`condition_on_previous_text=False`（防复读） |
| 源头防幻觉 | **soundtry** | 没人声的地方根本不送识别器；`looks_hallucinated()` 正则 |
| 事后防幻觉 | **better-ears** | 20 条中英词表 + 长度判断，比 soundtry 更全 |
| VAD | **better-ears** | `voiceBlocks()` 有动态范围保护（<6dB 不切，整段交识别器），治"BGM 铺满把人声切光" |
| 内容判别 | **better-ears** | `contentKind()` 投票：语音/音乐 → 决定要不要开分离 |
| 快档降级 | **better-ears** | 三通道抽象，宿主 `speechToText`（SenseVoice）当"来不及"档 |
| 时间码 | **see-now** | `seg-<epochMs>.wav`：WASAPI 静音不推数据，样本计时会漂 |

**跨模态点子（两边都没有，机制现成）**：用屏幕 OCR 的字幕做 whisper 的 `initial_prompt`（soundtry 已有 `--prompt`）。字幕与口播互相纠正。约束：只取最近一行、只在 OCR 稳定时用。

**代价**：Python 3.12 本机已有（`C:\Users\24206\AppData\Local\Programs\Python\Python312`）；磁盘 ~2.4GB；端到端延迟 2–2.5s；soundtry 是 CLI 不是服务，需要一个长驻 worker（约 100 行）import 它的函数，避免每句重启 Python。

**引擎定案（2026-11-21 03:36）**：

- **人声为主 → SenseVoice-Small**（宿主或 FunASR）：0.03×、不会复读、零部署；中文专训。
- **BGM 铺满 → faster-whisper large-v3-turbo + MDX 人声分离**：抗 BGM 的前提是**先分离**，turbo 单独跑照样掉字。
- **切换判据**：`contentKind` 判为音乐 / 分离后人声能量占比低 / SenseVoice 连续输出为空或异常短 → 升级到 turbo。
- **两个都常驻**（0.3G + 2.5G ≈ 2.8G，16G 显存无压力），不要每次切换重载模型。
- **降级链**：turbo(GPU) → SenseVoice → 无字幕（`cublas`/`cudnn` 缺失时 turbo 会退 CPU，1× 实时等于不可用，直接降级）。


### 三带已在 2026-11-21 采用

`src/ocr.mjs` 默认改成三带（top 0–0.22 / middle 0.22–0.78 / bottom 0.78–1.0），
**每条带各自两次一致、各自出事件**，事件带 `band` 字段。

理由：固定单一带换场景就失效（量过：视频的字在 0.3–0.7 与底部，桌面的字 18 行挤在 0.0–0.1）。
三带不猜位置，把"哪条是字幕"交给 AI 判断——与 streamvision 同路。
