# 声音只保留 faster-whisper large-v3-turbo，不做人声分离

三档引擎取舍之后只留一条链：WASAPI 环回 → better-ears 的 VAD / 分窗 / 幻觉过滤 → faster-whisper large-v3-turbo（GPU）。**不做 MDX 人声分离，不保留 SenseVoice 作快档。** 理由：内容判别加人声分离要多付约 1.7 秒/句和整套 ONNX 依赖，而主场景是游戏直播——主播说话占主导，BGM 是背景；SenseVoice 的保留价值只剩「GPU 不可用时的退路」，为了让那条退路成立要多养一套模型，不如改成明确报错。

**Consequences**

- **BGM 压过人声时会掉字**，且唱歌会被当说话转写——MV / 音乐区不适合这个方案。以后要补分离，它是一个开关，不是地基。
- GPU 依赖（`cublas` / `cudnn`）缺失时，faster-whisper 会退到 CPU int8，那是 1× 实时、等于不可用。这种情况必须**显式报错**，不许静默变成没有字幕。
- 时间码一律用 epoch 毫秒，不用样本数累加：WASAPI 静音时不推数据，样本计时会永久漂移。

## 2026-11-22 复核：结论不变，补三条落地结论

仍然只留 turbo 一条链。这轮把「声音差」查到底了，有三条与本文相关：

- **瓶颈不在录音，在解码宽度。** 同一轮真实环回音轨、同一把尺子（0–300 秒 / 827 bigram）：`beam_size=1` → 81.4%，`beam_size=5` → 83.6–84.0%（离线回放）；线上 5 分钟实测 **81.5% → 85.9%**，逐句命中 79.7% → 83.8%。`beam_size` 已抽成 `BEAM_SIZE` 常量并定为 **5**。再往上不划算：10 只高 0.5 点（在两次抖动 0.4 点之内）且 p90 翻倍，20 反而更差。
- **「干净 mp3 81.3% 是 turbo 天花板」这条作废。** 那是 beam 1 下的数，不是模型极限——85.9% 已经超过它。
- **明确不做**（用户 2026-11-22 决定）：不换 SenseVoice；不做热词/后处理纠错（只改字、补不了漏句）；**不引入 `initial_prompt`** —— 本项目不是只陪一部片子，prompt 会把结果硬拉向提示内容。同样，`language="zh"` 硬编码有同一类问题，已记待改。
